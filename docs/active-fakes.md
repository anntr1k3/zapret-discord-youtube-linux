# Активные fakes в GUI

Эквивалент пункта **«Replace active fakes»** (строка 7 матрицы `service.bat`
1.10.4) на вкладке **«Настройки»**, после явного чтения конфига.

Upstream 1.10.4 хранит выбор в файлах `bin/ACTIVE_DISCORD_UDP.bin` и
`bin/ACTIVE_GAME_UDP.bin`: пункт меню копирует выбранный `.bin` поверх активных
файлов и показывает текущий выбор, сопоставляя SHA-256 с остальными `.bin`. В
Linux-версии релиз на месте не изменяется: выбор хранится в конфиге, а runtime
подставляет постоянные копии при запуске.

## Что подменяется

- **Discord UDP** — значения `--dpi-desync-fake-discord` и
  `--dpi-desync-fake-stun` в стратегии. Это те же опции, которые в 1.10.4
  ссылаются на `ACTIVE_DISCORD_UDP.bin`.
- **GameFilter UDP** — значения `--dpi-desync-fake-unknown-udp` (профиль Game
  Filter UDP, в 1.10.4 — `ACTIVE_GAME_UDP.bin`).

Подменяются только значения, являющиеся ссылками на `.bin` из релиза
(`bin/*.bin` или `%BIN%*.bin`). Шестнадцатеричные литералы (`0x…`) и не
затронутые типы (`--dpi-desync-fake-tls`, `fake-quic`, `fake-http`, паттерны
`split-seqovl`) остаются без изменений. Если в текущей стратегии нет опций
выбранного типа, замена ни на что не влияет — GUI это показывает.

## Хранение и выбор

В конфиг добавляются необязательные ключи:

```ini
fakediscord=<SHA-256 выбранного .bin>
fakegameudp=<SHA-256>
```

Пустое значение или отсутствие ключа — поведение по умолчанию (upstream).
Значение — SHA-256 файла, который был скопирован при выборе в постоянные данные:

- `/etc/zapret-discord-youtube/fakes/ACTIVE_DISCORD_UDP.bin`
- `/etc/zapret-discord-youtube/fakes/ACTIVE_GAME_UDP.bin`

(в переносимой установке — `fakes/` внутри каталога программы). Имена файлов
совпадают с upstream-активными для узнаваемости, но лежат в постоянных данных,
поэтому обновление релиза их не затирает. Релиз, его `bin/` и пользовательские
списки при выборе и переключении не изменяются.

Выбрать можно только `.bin` из установленного релиза: helper принимает
SHA-256 и находит файл с таким хешем среди регулярных файлов `bin/` (без
symlink, до 8 МиБ). Произвольный путь через запрос передать нельзя. После
обновления набора стратегий список выбора автоматически соответствует новому
релизу; сохранённые копии продолжают работать, потому что это локальные
постоянные файлы.

Если текущий выбор не совпадает ни с одним `.bin` релиза (релиз изменился
настолько, что хеши не совпали), GUI показывает предупреждение с SHA-256 — так
же, как upstream сопоставляет выбор по хешу. Приложение при этом работает:
копия в постоянных данных валидна.

## Применение и восстановление

Кнопка **«Применить активные fakes…»** показывает подтверждение; может
потребоваться авторизация. Транзакция:

1. выбор проверяется (файл есть в релизе, конфиг не менялся с чтения,
   неселектируемые переопределения соответствуют своим файлам);
2. работающий сервис останавливается, остановленный не запускается;
3. файлы копируются атомарно (0600, fsync), затем обновляется конфиг;
4. конфиг валидируется целиком, сервис запускается заново.

Повтор идентичных настроек не перезапускает сервис. При неудачном запуске
восстанавливаются конфиг, прежние файлы fakes и работа сервиса. Правки других
процессов не перезаписываются при отказе: если конфиг или файл изменил кто-то
ещё, восстановление отменяется с объяснением.

Runtime проверяет SHA-256 активных файлов на каждом запуске сервиса: при
расхождении (например, файл подменили вручную) старт прерывается с понятной
ошибкой, а не подставляет другой пакет молча. Восстановление из GUI: перечитать
настройки и выбрать fake заново или вернуть «По умолчанию».

## Ограничения и совместимость

- Нужен runtime с маркером `# active fakes v1` и helper с capability
  `active-fakes-v1`. Старый helper не получает неподдерживаемые запросы: блок
  GUI отключается с объяснением. Обновление установленной копии не выполняется
  скрыто.
- Замена не является гарантией обхода: эффективность зависит от стратегии и
  провайдера. HTTP 200 не доказывает работу видео/голоса.
- Стратегии без соответствующих fake-опций показывают «не использует этот fake».
- Выбор ограничен файлами, которые уже поставляются с релизом; скачивание
  сторонних fake-пакетов не предусмотрено.

Повторять сценарий можно только root в отмеченном одноразовом госте с hostname
`zapret-integration` и маркером `/var/tmp/zapret-vm-provisioned`:

```sh
sudo python3 ci/vm_active_fakes_smoke.py --source /home/vmtest/checkout \
  --acknowledge-disposable-vm
```

Source должен содержать публичные данные/движок/ALT12 и тестовый legacy-конфиг.
Сценарий меняет гостевой systemd/firewall и не предназначен для рабочей машины.
