# Локальный набор исправлений безопасности

## Изменения поведения

- `conf.env` — данные `key=value`, а не Bash-скрипт. Допускаются пустые строки,
  комментарии с `#`, CRLF и отсутствие перевода строки в конце файла. Shell-код,
  кавычки, неизвестные/повторные ключи и неверные значения отклоняются.
- Обязательные ключи: `interface`, `gamefiltertcp`, `gamefilterudp`, `strategy`.
  Булевы значения — `true`/`false`. Стратегия — имя `.bat` без пути.
  `firewall_backend` необязателен, по умолчанию `auto`; можно указать имя
  существующего модуля. Проверка конфига не изменяет файл.
- Автоподбор YouTube сохраняет текущую схему конфига через временный файл.
  Предыдущая конфигурация копируется в `conf.env.backup` перед заменой.
  При следующем успешном сохранении эта резервная копия обновляется.
- Статус и остановка `nfqws` проверяют путь `/proc/PID/exe`, а не подстроку в
  командной строке. Экземпляры с другим исполняемым файлом не останавливаются.
  Это Linux-специфичная проверка, не поддержка нескольких экземпляров с общим
  бинарником. Firewall по-прежнему использует общие имена таблиц и очередь.
- Создание широких NOPASSWD-правил отключено. Команды `setup-permissions status`
  и `setup-permissions remove` сохранены для миграции.

## Системный сервис

Все пять init-бэкендов перед установкой проверяют папку приложения и все её
родительские каталоги. Они должны принадлежать root, не разрешать запись группе
или остальным пользователям и не быть символическими ссылками. Те же ограничения
применяются ко всем файлам и вложенным каталогам приложения. Путь установки должен
содержать только латинские буквы, цифры, `/`, `_`, `-` и `.` — это ограничение
шаблонов init-систем.

**Установка сервиса из обычного пользовательского checkout теперь отклоняется.**
Проверка не запускает `chown`/`chmod` и не переносит файлы автоматически.
Администратор должен подготовить отдельную проверенную root-owned установку,
например в `/opt`, включая зависимости и валидный конфиг. Обновления и изменение
конфига в этой установке также требуют прав администратора. Не меняйте владельца
всего домашнего каталога ради прохождения проверки.

Для systemd добавлен отдельный [установщик](system-install.md), создающий
root-owned версии в `/opt` и постоянные данные в `/etc`. Прежний `service install`
не заменяет его. Узкий привилегированный helper пока не реализован. Изменение не
исправляет уже установленные сервисы и старые разрешения задним числом: их
необходимо отдельно проверить и переустановить.

## Старые разрешения

`setup-permissions status` показывает наличие старых настроек. `remove` удаляет
выделенный `/etc/sudoers.d/zapret`. Если обнаружен блок Zapret в общем
`/etc/doas.conf`, команда просит администратора удалить его вручную и возвращает
ошибку: автоматическое удаление диапазона строк могло затронуть чужие правила.
Ничего не удаляется при обычном запуске программы.

## Проверка без изменения системы

```sh
python3 ci/test_regressions.py
python3 ci/test_installer.py
```

Тесты используют временные файлы и подмены привилегированных команд. Они не
загружают и не запускают `nfqws`, не вызывают sudo и не изменяют firewall.
Для тестов и установщика нужен Python 3.9+; само приложение остаётся Bash-приложением.

Это усиление защиты, не полный аудит. Подготовка стратегий теперь сверяет digest
manifest и SHA-256 файлов, но независимая проверка цифровых подписей upstream,
изоляция нескольких экземпляров и полноценные сетевые проверки требуют отдельной
работы. [Автосинхронизация](strategy-sync.md) реализована как непривилегированная
подготовка с отдельным подтверждаемым применением. Жизненный цикл установщика проверен в настоящей KVM VM
на Ubuntu 24.04/nftables: [отчёт и ограничения](vm-validation-2026-11-09.md).
