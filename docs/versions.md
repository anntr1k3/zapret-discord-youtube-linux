# Версии приложения и данных Flowseal

На вкладке **«Обновления»** отдельно показаны:

- версия открытого Linux GUI;
- версия установленной системной копии приложения (она может отличаться от GUI,
  запущенного из checkout);
- локальный набор данных Flowseal: канал, tag, commit, источник;
- результат последней сохранённой успешной проверки Flowseal и её время;
- совпадение или различие ревизий данных.

Приложение сейчас имеет явную версию **`1.0.1-rc1`**, `release=false` в
`src/app-version.json`. Это обозначение разработки, **не выпуск 1.0** и не
версия Windows-набора Flowseal. Файл копируется установщиком вместе с `src`.
Отсутствие метаданных в старой системной копии показывается как неизвестная
версия; номер открытого checkout не приписывается установленному приложению.

Версия данных читается только из `zapret-latest/.flowseal-sync.json`, которую
создаёт синхронизатор. Без неё версия неизвестна: `LOCAL_VERSION` в старом
`service.bat`, имя каталога и tag в подготовленном пакете не доказывают версию
установленного набора. До установки источник помечен как **локальный checkout**.
Чтение метаданных не исполняет nfqws, `.bat`, git или shell и не обращается в сеть.
JSON ограничен 4096 байтами; неправильный формат/схема не считаются успехом.

## Ссылки и сравнение

Показан фиксированный источник
`https://github.com/Flowseal/zapret-discord-youtube`.
Для канала `release` строится ссылка на `/releases/tag/<tag>`; для `main` —
на `/commit/<sha>`, без объявления ветки релизом. Произвольные URL из
метаданных не используются; tag, канал и commit проверяются. При отсутствии
валидных метаданных соответствующая ссылка скрыта. Открытие ссылки в браузере
происходит только по нажатию пользователя.

Разные commit означают **разные ревизии**, а не доказательство того, какая
новее. Сравнение выполняется с текущими локальными метаданными, не с сохранённым
в старом результате проверки `current_revision`: после применения обновления
надпись пересчитывается. Ошибка последней проверки не подменяется старой
успешной версией. Результат может быть кэшированным: время проверки показано,
не обещается постоянная связь с upstream.

Подготовленный пакет показывается отдельно от установленного. Если его
ревизия уже совпадает с текущей, он больше не предлагается как неприменённый;
его stage в пользовательском кэше автоматически не удаляется. Номер приложения
при подготовке или применении данных Flowseal не меняется.

Кнопки **«Проверить Flowseal»**, **«Подготовить обновление»** и
**«Применить подготовленное…»** относятся к данным стратегий. Проверка сохраняет
прежний 15-минутный кэш, ограничения GitHub и обработку rate limit;
применение требует отдельного подтверждения. Обновления самого Linux-приложения
здесь **не проверяются и не устанавливаются**; его доверенная релизная поставка
остаётся отдельной задачей до 1.0.

Повторять только в отмеченном одноразовом госте, с пользователем `vmtest` и
без установленного сервиса приложения:

```sh
sudo python3 ci/vm_versions_smoke.py --source /home/vmtest/checkout \
  --acknowledge-disposable-vm
```

Для воспроизведения исторического результата к этой команде добавляется
`--saved-check /var/tmp/zapret-update-check-result.json` — evidence предыдущей
VM-проверки таймера. Без этого флага используется обычная проверка latest.
Сценарий требует root, hostname `zapret-integration` и маркер
`/var/tmp/zapret-vm-provisioned`. На рабочей машине запускать нельзя.

Не проверены: открытие браузера, интерактивный polkit и полный путь GUI →
