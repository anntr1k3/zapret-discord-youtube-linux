# Автоматическая проверка обновлений

На вкладке **«Обновления»** доступны переключатель автоматической проверки,
следующее время запуска, последний сохранённый результат и обновление сведений.
Изменение расписания требует подтверждения, но не root: управляется только
пользовательский systemd. На рабочей машине при разработке таймер не включался.

## Проверка — не подготовка и не применение

Новый `zapret-update-check.timer` запускает `zapret-update-check.service`:

```text
/usr/bin/python3 …/src/lib/strategy_sync.py check --base … --cache … --channel release
```

Это только получение сведений о последнем релизе Flowseal и его commit.
Архив стратегий, IPSet и hosts не скачиваются, pending-пакет не создаётся.
Конфигурация приложения, выбранная стратегия, сервис и firewall не меняются.
Применение подготовленного пакета остаётся отдельным подтверждаемым действием.

Канал таймера — `release`. Общий кэш метаданных GitHub действует 15 минут,
сохраняются проверка HTTPS, ограничения адресов, обработка rate limit и
блокировка одновременного разрешения версии. Сохранённая ревизия сравнивается
с метаданными установленного набора. Если текущая ревизия неизвестна, GUI
говорит об этом, а не утверждает, что обновление доказанно необходимо.

Результат ручного и фонового `check` сохраняется атомарно с правами `0600` в
`~/.cache/zapret-strategy-sync/last-update-check.json` (учитывается
`XDG_CACHE_HOME`): статус, время UTC, версия/commit и результат сравнения.
Ошибка сети заменяет прежний успешный результат записью об ошибке.
Неудачный запуск самого systemd-сервиса, в том числе timeout, показывается
отдельно: прежний JSON не маскирует его успехом. Для перечитывания состояния
открытого окна есть кнопка **«Обновить сведения о проверке»**.

## Расписание и безопасность

- `OnCalendar=daily`, случайная задержка до 30 минут, `Persistent=true`.
- Пропущенный запуск может произойти сразу после включения или следующего входа.
- Работа без входа пользователя (`linger`) автоматически не включается.
- Показаны отдельно включённость при входе и фактическая активность таймера.
- Нет доступа к пользовательскому systemd — состояние неизвестно, кнопка
  отключена с объяснением, а не показана как успешно выключенная.
- Юниты создаются в `$XDG_CONFIG_HOME/systemd/user` либо `~/.config/systemd/user`.
- Юниты со сторонним содержимым, symlink, другим расположением загруженного
  unit или дополнительными drop-in настройками автоматически не заменяются.
- Пути экранируются для systemd, включая пробелы, кавычки, `%` и `$`.
- При неудачном переключении восстанавливаются прежние файлы и состояние
  таймера; сбой восстановления сообщается отдельно.
- Выключение останавливает только timer. Уже выполняющийся `check` может
  завершиться; его результат и файлы юнитов сохраняются.

Старый CLI `timer-install` по-прежнему создаёт **другой** таймер:
`zapret-strategy-sync.timer`. Он **скачивает и проверяет стратегии**, но никогда
не применяет их. GUI отдельно сообщает, если он включён; новый переключатель
не включает, не выключает и не переписывает его. Поэтому выключенная
автоматическая проверка не означает отключение ранее настроенной подготовки.
См. [синхронизация стратегий](strategy-sync.md).

Этот блок проверяет данные Flowseal, не обновления самого Linux-приложения.
Разделение версий приложения/данных и релизная поставка остаются отдельными
задачами матрицы 1.0.
