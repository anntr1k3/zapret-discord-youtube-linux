# Обслуживание кэша Discord

На вкладке **«Диагностика»**, отдельно от читающего отчёта:

1. Закройте Discord, включая оставшийся процесс в трее.
2. Нажмите **«Проверить профили и кэш Discord»**.
3. Выберите экземпляр: показаны конкретные каталоги, число файлов и логический
   размер. Проверка сама ничего не удаляет.
4. **«Очистить выбранный кэш…»** показывает отдельное подтверждение с путями.

Удаляются только **`Cache`**, **`Code Cache`**, **`GPUCache`** выбранного профиля.
Не затрагиваются Local Storage/leveldb, Cookies, Session Storage, settings,
токены, другие каталоги профиля и другие экземпляры Discord. Кэш не пересоздаётся,
Discord автоматически не запускается. Полезность очистки для конкретной сетевой
проблемы не гарантируется.

Нет root, pkexec, завершения клиента или произвольного выбора каталога для
удаления. Backend принимает идентификатор из фиксированного списка и токен
предпросмотра, **не путь из окна**. Очистка от root явно запрещена. Рабочий
кэш при разработке не сканировался и не удалялся.

## Поддерживаемые layouts

Проверяются только следующие существующие профили текущего пользователя:

| Экземпляр | Путь относительно HOME |
| --- | --- |
| Native Stable | `.config/discord` |
| Native PTB | `.config/discordptb` |
| Native Canary | `.config/discordcanary` |
| Native Development | `.config/discorddevelopment` |
| Flatpak Stable | `.var/app/com.discordapp.Discord/config/discord` |
| Snap Stable | `snap/discord/<revision>/.config/discord` через разрешённый `current` |

Для native учитывается `XDG_CONFIG_HOME`, только если он внутри HOME. HOME
канонизируется и должен принадлежать пользователю без записи группы/остальных.
Пути за пределами HOME, нестандартные обёртки/профили, дополнительные Flatpak
App ID и неизвестные layouts автоматически не угадываются. Наличие каталога
не является проверкой установленного пакета или его версии.

Snap `current` — единственное разрешённое перенаправление: только относительный
номер ревизии (`123` или локальный `x1`), без `/`, `..` и произвольного назначения.
В предпросмотр попадает конкретная ревизия, а не абстрактный `current`.
Смена ревизии после просмотра отменяет подтверждение; старые ревизии не чистятся.

Сверка источников 13 ноября 2026:

- [Flathub manifest](https://github.com/flathub/com.discordapp.Discord/blob/master/com.discordapp.Discord.yaml)
  задаёт `com.discordapp.Discord`; [документация Flatpak](https://docs.flatpak.org/en/latest/sandbox-permissions.html)
  описывает per-app `config` в `~/.var/app/$FLATPAK_ID`.
- [Snapcrafters manifest](https://github.com/snapcrafters/discord/blob/master/snap/snapcraft.yaml)
  и [launcher](https://github.com/snapcrafters/discord/blob/master/snap/local/bin/launcher)
  подтверждают snap `discord` с GNOME extension и запуском Discord. Это
  community-пакет, не утверждение об официальной поддержке Discord.

Ссылки на изменяемые ветки — контекст для выбранных layouts, не доказательство
пути каждой версии клиента. Проверены искусственные структуры ниже;
реальные Discord-пакеты в этой проверке не устанавливались.

## Защита перед удалением

- Проверяются только метаданные кэша, без чтения его содержимого или хранилищ
  токенов. Максимум 50000 элементов и глубина 32; большие деревья отклоняются.
- Снимок SHA-256 связывает экземпляр, путь и метаданные дерева. До удаления он
  пересчитывается. Обычная правка/подмена дерева после просмотра блокирует очистку.
- Родительские каталоги открываются по дескрипторам с `O_DIRECTORY|O_NOFOLLOW`.
  Внутри профиля и кэша symlink не разрешены. Проверяются владелец, права,
  inode/device, типы; hardlink, FIFO/сокеты/устройства и небезопасные права
  блокируют весь экземпляр, а не молча пропускаются.
- Читается mountinfo; вложенные mountpoints, в том числе same-filesystem bind
  mounts, и переходы на другой device запрещены. Недоступные сведения о
  монтировании означают отказ, а не разрешение очистки.
- По доступному procfs проверяются известные имена Discord и generic `electron`
  текущего UID. При совпадении либо неполной проверке удаление заблокировано.
  Проверка повторяется перед подготовкой и перед удалением. Она консервативна:
  другие Electron-приложения тоже могут блокировать действие. Никакой процесс
  не завершается; принудительного override нет.

Выбранные каталоги временно переименовываются в приватный
`.zapret-discord-cache-<uuid>` внутри того же профиля, повторно проверяются,
затем удаляются по дескрипторам. Временный каталог **не резервная копия**,
корзина не используется. Новый кэш, который клиент успел создать по прежнему
имени, при восстановлении не перезаписывается.

**Удаление не является полностью обратимой транзакцией.** Ошибка до удаления
возвращает оставшиеся каталоги, если это безопасно. При поздней ошибке уже
удалённые файлы не восстанавливаются: сообщение содержит фактическое число
удалённых файлов. Если прежнее имя занято новым кэшем или восстановление
невозможно, остаток сохраняется во временном каталоге, его путь показывается
в подробностях ошибки. Автоматического повторного удаления такого остатка нет.

Процессы и дерево могут измениться после проверки; поэтому клиент должен
оставаться закрытым до конца операции. Это не гарантия атомарности относительно
злонамеренного процесса с тем же UID или root. Защита не претендует на управление
клиентами, скрытыми в другом PID namespace, переименованными/нестандартными
обёртками, или на безопасное продолжение при внешних изменениях mount namespace.
Неподдерживаемая среда должна разбираться отдельно, без снятия проверок вслепую.

## Проверки 13 ноября 2026

**26 офлайн-тестов** в `ci/test_discord_cache.py`, только с временными профилями:
обнаружение/счётчики, все шесть layouts и XDG-путь, сохранение всех не-cache файлов,
no-op, дрейф снимка, неверные id/token, запущенные/неизвестные процессы, root,
symlink/выход Snap, hardlink, FIFO, mountpoints, права, лимиты обхода,
частичный сбой, восстановление без перезаписи нового кэша, подмена root-каталога,
сбой открытия staging и недоступность системных наблюдений, независимый деморежим.

Полный набор — **313 тестов OK**, GTK demo smoke — **27 операций PASS**,
включая имитацию обнаружения/подтверждённой очистки и недоступность повторной
кнопки после пустого результата. Smoke не читает рабочие профили и не нажимает
реальные диалоги подтверждения мышью.

### Отмеченная VM

`ci/vm_discord_cache_smoke.py`: **20 PASS** в Ubuntu 24.04/KVM, ядро
`6.8.0-147-generic`. Временный HOME принадлежал обычному `vmtest`. Ни реальный
Discord, ни реальные пользовательские токены/кэши не использовались.

Проверены настоящие файловые операции во всех layouts; sentinel-файлы в
Local Storage, Cookies, settings, Session Storage и вне профиля остались
побайтно неизменны. Созданный тестом процесс с comm `Discord` был найден через
настоящий procfs; очистка его не завершила и ничего не удалила. Сам тест потом
завершил только собственного дочернего имитатора.

Проверены устаревший токен, symlink наружу, выход через Snap `current`, настоящий
bind mount с данными вне кэша, отказ реального root-вызова и инъекция ошибки
после фактического unlink. Сбой сообщил `удалено файлов: 1`, оставшиеся каталоги
вернулись без изменения настроек. После отдельных успешных очисток временные
staging-каталоги отсутствовали, повтор пустого кэша был no-op.

Firewall, hosts и timestamps не изменились; системный сервис не запускался.
Bind mount размонтирован, синтетический HOME удалён, имитатора Discord и nfqws
нет, unit not-found/inactive, nft ruleset пуст. VM выключена.
