# Автосинхронизация стратегий Flowseal

Механизм разделён на **проверку**, **подготовку** и **явно подтверждаемое
применение**. Автоматика может скачивать и проверять новые стратегии, но не
перезапускает рабочий сервис без команды пользователя.

Это синхронизация данных, не автоматическое обновление кода адаптера или
бинарника `nfqws`. Доступна также [графическая оболочка](gui.md).

## Что обновляется

- Поддерживаемые стратегии `general*.bat` и `discord*.bat`.
- Обычные списки `lists/*.txt`, кроме трёх пользовательских `*-user.txt`.
- Файлы фейковых пакетов `bin/*.bin`.

Windows EXE/DLL/SYS, `service.bat`, PowerShell и прочие исполняемые файлы не
устанавливаются и не запускаются. `.bat` разбираются как текстовые данные.
Преамбула Windows не исполняется; из единственной поддерживаемой команды
`start ... winws.exe` извлекаются разрешённые параметры стратегии.

По умолчанию выбирается последний опубликованный **релиз**, затем его тег
разрешается в неизменяемый commit SHA. Для более свежего, потенциально
экспериментального состояния есть `--channel main`. Переключение на main
само по себе не делает стратегии совместимыми с установленным движком.

## Однократное обновление адаптера

Уже установленная старая версия должна один раз получить новый runtime и
команду `apply-strategies`. Из проверенного подготовленного checkout:

```sh
cd ~/Документы/zapret-discord-youtube-linux
sudo python3 install.py update --source "$PWD"
```

Это **обычное обновление всей подготовленной копии**: проверьте её движок,
стратегии и наличие выбранного профиля перед выполнением. Оно требуется только
для перехода на версию с синхронизацией, а не перед каждым обновлением Flowseal.
Пользовательские настройки и списки сохраняются установщиком.

Если системной установки ещё нет, сначала подготовьте и установите адаптер по
[основной инструкции](system-install.md). Первая версия применения стратегий
поддерживает только управляемую systemd-установку. Для ручного `service.sh run`
доступны проверка/подготовка, но автоматической перезаписи рабочего каталога нет.

## Проверка и подготовка без sudo

Из каталога проекта:

```sh
python3 sync.py check
python3 sync.py prepare
python3 sync.py status
```

Если `/opt/zapret-discord-youtube/current` существует, по умолчанию используется
установленная версия. Иначе — checkout, содержащий скрипт. Базу можно указать
явно через `--base PATH`; для подготовки в ней должен быть уже имеющийся
доверенный `nfqws`. Движок с сервера не скачивается.

Эквивалент без привязки к checkout, после обновления адаптера:

```sh
python3 /opt/zapret-discord-youtube/current/src/lib/strategy_sync.py prepare
```

Ключи:

```sh
python3 sync.py prepare --channel main
python3 sync.py prepare --base /opt/zapret-discord-youtube/current --cache /absolute/cache/path
```

`check` читает GitHub и показывает `revision`, `tag`, `current_revision`,
`update_available`. Если `current_revision` равен `null`, установленная копия
ещё не имеет метаданных этого механизма; это не доказательство её устаревания.

Проверка релиза и его commit SHA кэшируется на **15 минут** отдельно для каналов
`release` и `main`. `check` и `prepare` используют общий кэш: нажатие «Проверить»,
а затем «Подготовить» не расходует запросы API повторно. Результат проверки может
отставать от GitHub не более чем на время этого кэша; просроченный кэш не
используется вместо неудавшейся свежей проверки.

При `403 rate limit exceeded` или `429` приложение показывает понятное сообщение
и время следующей попытки в **UTC**. Оно учитывает `X-RateLimit-Reset` и
`Retry-After`; если сервер не сообщил срок, выдерживается пауза в одну минуту.
До указанного времени новые обращения к API блокируются локально для обоих
каналов, в том числе после перезапуска окна. Ограничение может быть общим для
внешнего IP, а не только для приложения. Пауза не гарантирует снятия ограничения
сервером к этому моменту. Другие ошибки `403` не объявляются исчерпанием лимита.

Файлы `target-release.json`, `target-main.json` и `github-rate-limit.json` в
пользовательском кэше хранят эти сведения. Уже подготовленный `pending.json` и
его stage при ошибке API сохраняются, но не считаются подтверждением свежести.
Сервис, текущая стратегия и firewall при проверке не изменяются. Автоматического
перехода на `main`, стороннее зеркало или применения старого пакета нет.

`prepare` скачивает архив конкретного commit, проверяет содержимое, разбирает
все профили и запускает существующий `nfqws --dry-run` для каждой стратегии
во всех четырёх сочетаниях Game Filter TCP/UDP. Технически передаётся также
`--qnum=220`, обязательный для проверки в nfqws v72.9; в режиме dry-run очередь
не открывается и демон не запускается. Неизвестный формат, неизвестный параметр,
отсутствующий файл или ошибка движка блокируют публикацию подготовленной версии.

Успешный результат содержит, например:

```json
{
  "status": "prepared",
  "revision": "<40-значный commit SHA>",
  "stage": "/home/user/.cache/zapret-strategy-sync/stages/<id>",
  "digest": "<64-значный SHA-256>",
  "strategies": 22
}
```

По умолчанию кэш находится в `$XDG_CACHE_HOME/zapret-strategy-sync`, либо
`~/.cache/zapret-strategy-sync`. `pending.json` — последняя подготовленная версия;
`last-check.json` — результат последней автоматической подготовки, в том числе
ошибка. При совпадении upstream, движка и версии парсера повторная подготовка
использует проверенный кэш. Повреждённый кэш пересоздаётся в новом каталоге без
удаления старого. Неиспользуемые старые stages автоматически не удаляются.

## Подтверждённое применение

Скопируйте **stage и digest из проверенного результата prepare**:

```sh
sudo python3 /opt/zapret-discord-youtube/current/install.py apply-strategies \
  --stage /home/user/.cache/zapret-strategy-sync/stages/EXACT-ID \
  --digest EXACT-SHA256 \
  --yes
```

`--yes` и digest обязательны. Не подставляйте SHA из непроверенного сообщения
или стороннего сайта. Digest связывает выбранный manifest со всеми файлами
подготовленной версии; он **не является цифровой подписью Flowseal**.
Доверие к источнику основано на HTTPS и фиксированном официальном репозитории.

Привилегированная часть:

1. Блокирует параллельные изменения установки.
2. Читает stage через закреплённые дескрипторы без следования symlink, с
   ограничениями размера, типов и имён; повторно сверяет SHA-256 всех файлов.
3. Повторно разбирает стратегии доверенным локальным парсером — не использует
   присланный Python/Bash-код и не выполняет Windows-команды.
4. Создаёт приватную копию **текущей установленной версии**, заменяя только её
   каталог стратегий. Не берёт движок и код приложения из пользовательского stage.
5. Проверяет наличие выбранного профиля и синтаксис текущим движком с реальными
   пользовательскими списками. Приватный root-каталог остаётся 0700; только для
   этой предварительной проверки nfqws получает `--dry-run --uid=0:0`, иначе его
   внутреннее понижение UID препятствовало бы чтению приватного кандидата.
6. Сохраняет резервную копию данных, создаёт отдельную защищённую версию и
   повторяет dry-run с обычным поведением UID уже по окончательным публично
   доступным путям. Эта проверка обязательна и всё ещё не останавливает сервис.
   При отказе доступа кандидат удаляется, рабочая версия остаётся активной.
7. Только затем активирует новую версию проверенным механизмом установщика.
   При ошибке запуска восстанавливает предыдущую. В рабочий nfqws проверочный
   `--uid=0:0` не передаётся.

Сетевых запросов в привилегированной части нет. Неактивный сервис не запускается;
состояние автозапуска сохраняется. Повторное применение того же digest — no-op.
При выбранной пользовательской стратегии из `custom-strategies` применение в
этой версии отклоняется: её совместимость с новым набором данных не доказана.
Сами пользовательские стратегии при синхронизации не удаляются.

Файлы из `/etc/zapret-discord-youtube/user-lists` и конфиг не перезаписываются.
Пользовательский список с тем же именем, что upstream-список, остаётся локальным
переопределением и может намеренно перекрывать обновлённый список.

Откат — стандартный, без восстановления старых пользовательских данных:

```sh
sudo python3 /opt/zapret-discord-youtube/current/install.py rollback
```

## Автоматическая ежедневная подготовка

Команды выполняются **без sudo**, в пользовательском сеансе:

```sh
python3 /opt/zapret-discord-youtube/current/src/lib/strategy_sync.py timer-install
systemctl --user daemon-reload
systemctl --user enable --now zapret-strategy-sync.timer
```

Это таймер **подготовки**, не новый GUI-переключатель check-only проверки.
Для проверки без скачивания предусмотрен отдельный `zapret-update-check.timer`;
см. [автоматическая проверка](automatic-update-check.md). Её результат хранится
отдельно в `last-update-check.json`; `last-check.json` сохраняет прежнее значение
результата подготовки.

Создаются пользовательские `zapret-strategy-sync.service` и `.timer`. Чужие unit
с такими именами не перезаписываются. Генерация файлов сама не включает таймер:
включение выполняется отдельной явной командой выше.

Таймер запускает **только prepare**, ежедневно со случайной задержкой до 30 минут.
Первый пропущенный запуск может произойти после входа в сеанс. Linger не
включается, root-сервис для обновлений не создаётся, живой zapret не останавливается.
Срок проверки и её результат видны в пользовательском журнале и `status`.

```sh
# Проверить сейчас
systemctl --user start zapret-strategy-sync.service

# Расписание и сообщения
systemctl --user list-timers zapret-strategy-sync.timer
journalctl --user -u zapret-strategy-sync.service -n 50 --no-pager

# Выключить автоматику (не останавливает сам zapret)
systemctl --user disable --now zapret-strategy-sync.timer
```

Для остановки уже идущей подготовки отдельно:
`systemctl --user stop zapret-strategy-sync.service`.

## Совместимость и границы

- Разрешён небольшой явный набор параметров; неизвестные возможности требуют
  обновления парсера, а не молчаливого пропуска. Параметры запуска демона,
  пользователей, очереди, системного fwmark и авто-записи hostlist запрещены.
- Новые стратегии используют `strategies.json` и безопасную передачу argv,
  сохраняя L3/L7-only профили, порядок и повторения параметров. Старые локальные
  `.bat` вне синхронизированного каталога продолжают использовать прежний парсер.
- Поддерживаются стандартные `%BIN%`, `%LISTS%`, `%GameFilter%`, `%GameFilterTCP%`
  и `%GameFilterUDP%`, одно winws-приложение и текущий формат разделения профилей.
- Размеры ограничены: архив/общие данные до 64 MiB, файл до 8 MiB, до 4096 записей;
  стратегии дополнительно ограничены по размеру/числу аргументов/профилей.
- SHA и dry-run не гарантируют эффективность обхода у вашего провайдера. После
  применения проверьте нужные ресурсы; при регрессии используйте rollback.
- Синхронизация не обновляет `hosts`, не чистит Discord-кэш и не заменяет остальные
  ещё не реализованные функции `service.bat`.

На рабочей машине в процессе разработки таймер не включался и обновления не
применялись. Подготовка 22 стратегий релиза 1.10.4, применение, перезагрузка,
откат и пользовательский таймер проверены в KVM на Ubuntu 24.04/nftables:
[отчёт](strategy-sync-validation-2026-11-10.md). Это не подтверждает обход DPI
у вашего провайдера. Проверки без root/сети:

```sh
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s ci -p 'test_*.py'
```
