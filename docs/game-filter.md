# Game Filter: режимы и диапазоны портов

В GUI добавлена вкладка **«Настройки»**. После явного чтения конфигурации доступны:

- выключенный режим;
- только TCP;
- только UDP;
- TCP и UDP;
- отдельные диапазоны TCP и UDP.

Значения — номера портов 1–65535 и возрастающие диапазоны через запятую,
например `1024-1934,1936-65535`. Пустые значения, пробелы внутри строки,
ведущие нули, обратные диапазоны и shell-текст отклоняются. Ограничения:
до 512 символов и до 128 элементов в каждом поле.

Оба диапазона сохраняются даже в выключенном режиме. Выбор режима и ввод текста
сами не меняют систему: нужна кнопка **«Применить Game Filter…»**, подтверждение
и административная авторизация. Увеличение диапазонов затрагивает дополнительный
трафик, поэтому включение фильтра само по себе не является рекомендацией для
любого подключения.

## Конфиг и совместимость

Существующие boolean-поля сохранены. Добавлены необязательные ключи:

```ini
gamefiltertcp=true
gamefilterudp=false
gamefiltertcp_ports=1024-1934,1936-65535
gamefilterudp_ports=1024-65535
```

Если новых ключей нет, каждый диапазон равен `1024-65535`: старый конфиг не
требует миграции. Диапазоны используются и legacy Bash-парсером, и безопасным
скомпилированным runtime. `%GameFilterTCP%` и `%GameFilterUDP%` независимы;
общий `%GameFilter%` при включённом TCP использует TCP-диапазон, иначе — UDP,
как в закреплённом эталоне Flowseal 1.10.4.

Помощник сообщает поддержку через capability `game-filter-ranges-v1`. Если
установлена старая копия, новый GUI показывает объяснение и не разрешает
применение этих настроек. Обновление установленной копии автоматически не
выполняется. До согласованного обновления функцию можно посмотреть в `--demo`.

Установщик не переключает конфиг с новыми ключами на runtime без поддержки
диапазонов: проверяется маркер `# game filter ranges v1` до остановки сервиса.

## Сохранность данных

Привилегированная операция `set-game-filter` принимает только режим, два
диапазона и SHA-256 прочитанного конфига. Другие поля отклоняются.

До остановки сервиса проверяются токен актуальности и весь кандидат конфига.
Сохраняются профиль, остальные настройки, комментарии, окончания строк,
права/владелец файла и состояние автозапуска. Создаётся штатная резервная копия.
Активный сервис перезапускается, неактивный не запускается; повторное применение
идентичных значений не вызывает перезапуск. При ошибке запуска восстанавливаются
предыдущие байты конфига и предпринимается восстановление сервиса. Ошибка
восстановления не скрывается.

сохранность профиля/автозапуска, отклонение неверного диапазона и устаревшего
токена без изменения MainPID, сохранность отдельного nfqws на очереди 221 и
посторонней nftables-таблицы. Дважды намеренно вызван одноразовый сбой запуска
через тестовый `ExecStartPre`; прежний конфиг и работа сервиса восстановлены.

Синхронизированный каталог в этом прогоне создан из публичных данных локальной
копии 1.9.9a с явно тестовым revision `aaaa…`, а не загружен как новый релиз с

### Найденная ошибка восстановления

Первый VM-прогон выявил: после неудачного старта `stop` может выгрузить unit,
после чего `reset-failed` отвечает `Unit … not loaded`. Байты конфига уже
восстанавливались, но запуск прежнего варианта не выполнялся из-за этой ошибки.

Причина подтверждена отдельным экспериментом с настоящим systemctl. Теперь
после попытки неудачного запуска `reset-failed` выполняется **до** повторного
`stop`, затем восстанавливается конфиг и запускается прежний вариант. Если
попытки запуска ещё не было, лишний `reset-failed` не вызывается. Добавлен
регрессионный тест, моделирующий выгрузку unit; исправление повторно проверено
для legacy и compiled в VM. Помощник также сохраняет stderr systemctl в ошибке.

### Воспроизведение и свидетельства

Сценарий VM разрешён только root в одноразовом госте с hostname
`zapret-integration`, маркером `/var/tmp/zapret-vm-provisioned` и явным флагом:

```sh
sudo python3 ci/vm_game_filter_smoke.py --source /home/vmtest/checkout \
  --acknowledge-disposable-vm
```

Не запускайте его на рабочей системе. Он устанавливает/удаляет гостевой сервис
и временно меняет гостевой systemd/firewall. В source нужна подготовленная
публичная копия с `general_alt12.bat`, nfqws и тестовым конфигом; личные списки
и конфигурация рабочего компьютера в VM не передавались.
