# Обновление hosts из GUI

На вкладке **«Настройки»** после чтения настроек доступна кнопка
**«Проверить и обновить hosts…»**. Она реализует Linux-эквивалент строки 9
Flowseal `service.bat` 1.10.4. Рабочая установленная копия при разработке
не обновлялась. Офлайн, GTK demo smoke и отдельная VM проверены;
пользовательская приёмка остаётся впереди.

## Загрузка и предпросмотр

Обычный пользовательский процесс получает только фиксированный источник:

```text
https://raw.githubusercontent.com/Flowseal/zapret-discord-youtube/refs/heads/main/.service/hosts
```

Загрузка запускается по нажатию, не в фоне автоматически. Используется общий
HTTPS-валидатор адресов и перенаправлений Flowseal. Принимается UTF-8,
IPv4/IPv6 и корректные имена узлов. HTML, пустые наборы, NUL и управляющие
символы, некорректные адреса/имена и служебные маркеры отклоняются. Лимиты:
1 MiB, 20000 строк, 50000 имён, до 64 имён на строку. BOM удаляется,
окончания строк нормализуются в LF; комментарии сохраняются.

Проверенные байты атомарно сохраняются с правами `0600` в пользовательский
кэш `~/.cache/zapret-strategy-sync/hosts-service.txt` (с учётом
`XDG_CACHE_HOME`). Неудачная проверка не заменяет предыдущий stage.
Команда `fetch-hosts` отказывается скачивать от root.

Окно показывает число записей, размер, SHA-256, различия управляемого блока
(до 400 строк diff), конфликты имён с записями вне блока и предупреждение
о существующих записях YouTube. Отмена ничего не применяет.
**«Экспортировать…»** сохраняет скачанный нормализованный список в выбранный
пользователем файл, не меняя `/etc/hosts`; запись экспорта атомарна,
symlink назначения отклоняется. Экспорт не является копией всего `/etc/hosts`.

## Подтверждённая запись

**«Применить»** вызывает только установленный root-помощник через `pkexec`.
Код пользовательского checkout не повышается до root. Старый помощник без
capability `hosts-update-v1` отключает кнопку с объяснением; автоматического
обновления установленной копии нет.

Запрос содержит абсолютный путь stage, SHA-256 его байтов и SHA-256 именно
тех байтов текущего hosts, по которым построен предпросмотр. Помощник:

1. Открывает stage без следования конечному symlink, проверяет тип и владельца
   по открытому дескриптору; root-owned stage запрещён. Чтение ограничено размером.
2. Повторно валидирует формат, нормализацию и SHA-256.
3. Требует обычный root-owned `/etc/hosts` без записи группы/остальных;
   symlink и специальные файлы запрещены. Проверяет токен текущего hosts.
4. Заменяет только блок между маркерами:

   ```text
   # BEGIN zapret-discord-youtube managed hosts
   …скачанные записи…
   # END zapret-discord-youtube managed hosts
   ```

   Если блока нет, добавляет его в конец с разделяющими переводами строк.
   Все исходные байты вне блока сохраняются. Дублированные, непарные и
   переставленные маркеры запрещают запись. Чужие конфликтующие записи
   не удаляются автоматически.
5. При совпадении результата не пишет файл и не создаёт резервную копию.
6. До изменения сохраняет полный прежний файл с правами `0600` в
   `/var/lib/zapret-discord-youtube/hosts-backups/hosts-<идентификатор>`.
   Повторно проверяет текущие байты и метаданные, затем атомарно заменяет файл
   с сохранением владельца, группы и прав. При ошибке записи пытается
   восстановить прежние байты; ошибка восстановления показывается отдельно.

Сервис **не перезапускается**, конфиг и firewall не изменяются. Транзакция
не зависит от корректности `conf.env`, но требует управляемую установку.
Приложения могут кэшировать DNS: успешная запись не доказывает немедленного
изменения их поведения или эффективности обхода DPI. Необычные контейнерные
и immutable-конфигурации не исправляются автоматически. Резервные копии
не очищаются по расписанию.

## Что проверено

Офлайн: `ci/test_hosts_update.py`, **24 теста** с временными файлами, без
записи рабочего `/etc/hosts`. Покрыты нормализация, лимиты, отказы валидатора,
сохранение чужих байтов, идемпотентность, маркеры, конфликты/YouTube,
фиксированный URL, права stage, резервная копия и права назначения,
устаревшие токены, дрейф stage, symlink, небезопасный владелец/права,
root-owned stage, восстановление после имитированного сбоя замены,
независимость от конфига, экспорт и сохранение существующего файла при его
ошибке. Регрессионный тест привязывает токен к байтам предпросмотра.

Полный офлайн-набор: **210 тестов**. GTK demo smoke: **20 операций**,
включая имитацию загрузки/применения hosts, проверку недоступности кнопки
до чтения настроек и со старым помощником, создание диалога предпросмотра.

## Проверка в VM 12 ноября 2026

`ci/vm_hosts_update_smoke.py` прошёл **47 утверждений** в новой отмеченной
одноразовой KVM VM: Ubuntu 24.04, ядро `6.8.0-147-generic`, QEMU 10.2.1.
Официальный минимальный cloud-образ проверен по опубликованному SHA-256:
`406630c08b5e545fcc7209854b129d47e3af822db128c9f19336593b5a2d3fe0`.
QEMU распакован локально без установки пакетов на рабочий хост.

Реальная загрузка как `vmtest` вернула **80 записей, 3185 байт**, SHA-256:

```text
e7dcca4f85f425ddb641586823d15a66618eaec4df010027ad95f9cc1af489a9
```

Проверены установленный изолированный root-помощник и capability; отказы
при устаревшем токене, неверном SHA-256, пустом наборе, symlink stage,
root-owned stage и чужой правке после просмотра; применение при остановленном
сервисе; точное сохранение внешних байтов, включая CRLF и не-UTF8 комментарий;
полная приватная резервная копия, сохранение владельца/группы/прав; no-op
без нового backup и изменения inode/mtime. При работающем настоящем nfqws
hosts обновился без смены MainPID. Конфиг, списки и дерево релиза не изменились.

Намеренный сбой введён **после реального атомарного replace** в отдельном
изолированном Python-процессе, импортирующем установленный помощник.
Установленные исходники не модифицировались. Проверены восстановление всех
прежних байтов hosts, сохранение работающего процесса и последующее успешное
применение. Повреждённые маркеры и world-writable назначение отклонены.
Посторонний nfqws на другой очереди и nftables-таблица пережили операции.
Удаление установки сохранило hosts и резервные копии.

Сценарий в `finally` восстановил исходные байты, владельца и права hosts гостя,
удалил сервис и sentinel-ресурсы. После прогона: `LoadState=not-found`,
`ActiveState=inactive`, нет nfqws, `nft list ruleset` пуст. VM выключена.

Повторять только от root в одноразовом госте с hostname `zapret-integration`
и маркером `/var/tmp/zapret-vm-provisioned`:

```sh
sudo python3 ci/vm_hosts_update_smoke.py --source /home/vmtest/checkout \
  --acknowledge-disposable-vm
```

Сценарий требует чистую установку (без каталога данных приложения),
пользователя `vmtest` и подготовленные зависимости/стратегию в исходниках.
Он меняет гостевые `/etc/hosts`, systemd и firewall: **не запускать на рабочей
машине**.

Границы проверки: интерактивный polkit и полный путь GUI → pkexec → помощник,
системный диалог экспорта, пользовательская приёмка и реальная работа DNS/DPI
не проверены. Успешная загрузка и запись не доказывают сетевую доступность.
