# Графический интерфейс

**Цель 1.0 расширена:** полное покрытие пользовательских функций Flowseal
`service.bat` с Linux-эквивалентами. Текущее окно — только первый этап;
[матрица функций и порядок реализации](gui-parity-1.0.md) фиксирует оставшуюся работу.

Первая версия GUI на Python + GTK4/libadwaita: состояние systemd-сервиса,
запуск/остановка/перезапуск, выбор установленной стратегии, автозапуск,
настройки Game Filter и IPSet, проверка/подготовка/применение стратегий Flowseal и последние сообщения
журнала. Интерфейс — на русском языке.

## Запуск из checkout

На Ubuntu/Debian нужны `python3-gi`, `gir1.2-gtk-4.0` и `gir1.2-adw-1`.
Нужна libadwaita **1.5 или новее** (используется Adw.AlertDialog).
Проверено на GTK 4.22 / libadwaita 1.9 в GNOME Wayland.

```sh
cd ~/Документы/zapret-discord-youtube-linux
python3 gui.py --demo
```

Демо целиком работает в памяти: не обращается к systemctl, сети, конфигу,
кэшу или firewall. Можно нажимать все кнопки без административных действий.
Данные сбрасываются при закрытии. Для настоящего режима:

```sh
python3 gui.py
```

**Не используйте sudo для окна.** Запуск от root отклоняется. При открытии
настоящего окна выполняются только локальные непривилегированные чтения статуса;
авторизация, скачивание и изменение состояния автоматически не запускаются.
Проверка и подготовка обновлений обращаются к GitHub только по кнопке.

## Системная установка

Установка остаётся отдельной ручной CLI-операцией по
[инструкции](system-install.md). Не заменяйте рабочий набор зависимостей ради GUI.
Если установки ещё нет, сначала остановите ручной запуск и проверьте сохранённый
профиль. GUI не управляет процессами, запущенными вручную через `service.sh run`.

Для существующей управляемой установки нужно вручную обновить её из проверенной
подготовленной копии, чтобы включить `src/gui/privileged.py`. Это обновляет всю
копию приложения, а не только GUI; проверьте её содержимое перед выполнением:

```sh
sudo python3 install.py update --source "$PWD"
```

Установленный интерфейс запускается без checkout:

```sh
python3 /opt/zapret-discord-youtube/current/src/gui/launch.py
```

Необязательный ярлык для текущего пользователя (только после установки):

```sh
mkdir -p ~/.local/share/applications
cp /opt/zapret-discord-youtube/current/src/desktop/zapret-gui.desktop \
  ~/.local/share/applications/zapret-gui.desktop
```

Ярлык автоматически не устанавливается; после удаления приложения удалите его
вручную. После обновления приложения рекомендуется переоткрыть окно.

## Авторизация и сохранность настроек

- Старт/стоп/перезапуск — фиксированный systemd unit и штатная авторизация
  systemctl/polkit. На системе нужен работающий агент авторизации.
- Чтение конфигурации — явная кнопка «Прочитать настройки…»: конфиг обычно
  недоступен обычному пользователю. На старте окно не вызывает запрос пароля.
- Изменение профиля/автозапуска и применение обновлений — отдельный помощник через
  `/usr/bin/pkexec /usr/bin/python3 -I` из root-owned управляемой версии в `/opt`.
  Код помощника из пользовательского checkout никогда не повышается до root.
- Нет собственного широкого polkit-правила без пароля. Используется системная
  политика pkexec для запуска Python; она может запрещать операцию. Ограничение
  действий обеспечивается помощником, а не специальным polkit action ID.
- Протокол помощника принимает ограниченный JSON с фиксированными полями, без
  произвольных команд, unit, путей конфигурации или установки/удаления приложения.
  Для применения передаются только выбранный stage и digest; они повторно
  проверяются существующим установщиком.
- Смена профиля сохраняет остальные строки и права конфигурации, проверяет токен
  SHA-256 от ранее прочитанного конфига. При внешнем изменении перечитайте настройки.
  Только активный сервис перезапускается; при ошибке восстанавливаются прежние
  настройки и предпринимается восстановление сервиса. Сбой восстановления
  показывается как ошибка, а не как успех.
- Автозапуск не запускает и не останавливает сервис. Отмена авторизации считается
  ошибкой; интерфейс перечитывает состояние после операции.
- Долгие операции выполняются последовательно в фоновом потоке. Пока операция
  идёт, закрытие окна отклоняется, чтобы не оборвать административную транзакцию.
  При зависшей/долгой сети нужно дождаться таймаута; принудительной отмены нет.

## Сообщения в окне

На вкладке **«Настройки»** доступны режимы и отдельные диапазоны Game Filter
после чтения конфига. Старый установленный помощник не получает неподдерживаемый
запрос: редактирование отключается с объяснением. Подробности, безопасность и
проверки: [Game Filter](game-filter.md).

Там же доступны [режимы IPSet](ipset-modes.md): loaded/none/any. Списки не
перезаписываются при переключении, для loaded показываются источник и SHA-256.
Кнопка **«Обновить список IPSet…»** скачивает и проверяет основной набор, затем
показывает предпросмотр и применяет его только после подтверждения; конфиг,
режим и исключения сохраняются. Подробности и ограничения:
[обновление IPSet](ipset-update.md).

Раздел **Hosts** предлагает загрузку, diff и экспорт списка Flowseal, затем
отдельное подтверждение изменения только управляемого блока `/etc/hosts`.
Полная резервная копия создаётся до записи, сервис не перезапускается.
Пройдены офлайн/GTK/VM-проверки; [подробности и ограничения](hosts-update.md).

Состояние сервиса отделено от результата последнего действия. Во время работы
внизу появляется полоса с названием операции и индикатором; после завершения
она скрывается. Успешные действия показывают короткое уведомление с конкретным
результатом. Обновление состояния не выводит постоянное «Готово».

При ошибке остаётся сообщение с кнопкой «Подробности»: текст можно выделить и
скопировать. Оно скрывается при начале следующей операции. Пока настройки не
прочитаны, выбор профиля пуст и недоступен — первый пункт списка больше не
выглядит как текущая стратегия. Чтение настроек не меняет сохранённый профиль.

На вкладке **«Обновления»** доступна [автоматическая проверка](automatic-update-check.md):
подтверждаемый переключатель пользовательского таймера, расписание и последний
результат. Он не скачивает и не применяет стратегии; старый таймер подготовки
показывается отдельно и не изменяется этим переключателем.

Там же [версии приложения и данных](versions.md) показаны раздельно:
открытый GUI (`1.0.0-dev`, не релиз), установленная системная копия,
локальный Flowseal и сохранённый результат проверки. Ссылки ведут к
фиксированному upstream-источнику, релизу или commit. Подготовка данных
не выдаётся за их установку, а проверка Flowseal — за обновление приложения.

На вкладке **«Сервис»** есть [расширенный статус](service-status.md): отдельное
читающее действие с авторизацией, не требующее предварительного чтения конфига.
Показаны systemd, nfqws в cgroup сервиса, SHA-256 движка, профиль, backend,
очередь и распознанные правила nftables/iptables. Ошибки доступа явно остаются
неизвестными состояниями. Это снимок, не полная диагностика и не проверка DPI.

Вкладка **«Диагностика»** собирает [локальный читающий отчёт](diagnostics.md)
без root, сетевых проб и исправлений. Доступны копирование и приватный
JSON-экспорт; пароли и чувствительные части proxy-URL скрываются, но отчёт
всё ещё может содержать локальные пути, DNS/proxy-хосты и PID. Перед передачей
его нужно просмотреть. Системные исправления пока впереди.

Там же отдельно доступны [обнаружение и очистка кэша Discord](discord-cache.md):
поддерживаемые native/Flatpak/Snap layouts, предпросмотр путей, проверка процессов
и явное подтверждение только Cache/Code Cache/GPUCache выбранного профиля.
Токены и настройки не удаляются, root и принудительное завершение не используются.
Работа с реальным клиентом ещё требует согласованной пользовательской приёмки.

## Проверки

Без GTK, сети и административных действий:

```sh
PYTHONDONTWRITEBYTECODE=1 python3 ci/test_gui.py
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s ci -p 'test_*.py'
```

В графическом пользовательском сеансе — создание настоящего окна и 31
последовательной операции независимого DemoBackend, с автоматическим выходом:

```sh
PYTHONDONTWRITEBYTECODE=1 python3 gui.py --demo --smoke-test
```

Без `--demo` этот флаг отклоняется. Проверка создаёт виджеты и обновляет их после
операций, но не имитирует мышь, ввод пароля или ответы в диалогах подтверждения.

16 ноября 2026 прошли **495 офлайн-тестов**, включая 36 тестов GUI backend/helper
и правил отображения, 19 отдельных IPSet-тестов, 16 тестов обновления IPSet и
22 теста активных fakes, 24 теста hosts, 14 тестов автоматической проверки,
18 тестов версий, 22 теста расширенного статуса, 29 тестов диагностики
(включая глубокие проверки cgroup/туннелей/портов), 26 тестов Discord cache,
17 тестов TCP timestamps, 55 тестов тестировщика стратегий, 27 тестов
контроллера/сигналов сеанса, 23 теста installed preflight/изоляции, 14 тестов
выбора очереди, 19 тестов транзакции сервиса, 3 теста systemd cgroup-stop,
6 тестов streaming-входа помощника и 10 тестов клиентского streaming runner
(подключён к GUI через `strategy-tester-v1`),
и GTK demo smoke на 31 операцию (включая отсутствие
выбранного профиля до чтения настроек, имитацию загрузки/применения IPSet,
уведомления и подробности имитированной ошибки). В отмеченной одноразовой KVM VM Ubuntu 24.04/nftables сценарий
`ci/vm_gui_smoke.py` проверил установленный помощник через изолированный Python:
чтение конфига, смену профиля у остановленного и работающего сервиса, отклонение
неверного имени/устаревшего токена/лишнего unit, автозапуск без остановки сервиса,
применение подготовленного Flowseal-пакета и откат. Запускался настоящий nfqws.
После проверки сервис удалён, VM выключена. Журнал: локальный временный файл
`/tmp/opencode/zapret-sync-vm/gui-helper.log` (не входит в репозиторий).

**Интерактивный диалог polkit, подтверждения мышью и полный путь GUI → pkexec →
помощник не проверены**: в VM помощник запускался напрямую от root; вызов pkexec
и отмена авторизации проверены подменами в офлайн-тестах. Проверки не доказывают
эффективность выбранной стратегии у провайдера.

## Ограничения первой версии

Кнопки ручного отката в GUI нет. Для перехода на старую версию приложения
пользователь выбирает нужный релиз на GitHub и устанавливает его отдельно.
Автоматическое восстановление при неудачном обновлении сохранено; технический
CLI-механизм отката также остаётся доступным.

Пока нет редактирования списков, полной диагностики и паритета с `service.bat`.
Эти ограничения текущего состояния не означают исключение паритета из цели 1.0.
Таймер ежедневной подготовки пока настраивается через CLI, см.
[синхронизацию](strategy-sync.md). При неизвестном формате или несовместимости
движка подготовка отклоняется; GUI сам движок не скачивает.

В списке выбора только поддерживаемые Linux-имена без пробелов, как требует
существующий валидатор конфига. Синхронизатор преобразует Windows-имена профилей
в канонические Linux-имена. Журнал ограничен 100 сообщениями, доступными текущему
пользователю; доступ к закрытому системному журналу автоматически не запрашивается.
