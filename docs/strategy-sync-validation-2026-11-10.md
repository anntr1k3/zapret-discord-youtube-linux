## Найденные нюансы и проверки защиты

Свежие стратегии содержат `--filter-l3` перед TCP-фильтром и L7-only профили.
Новый компилятор сохраняет их порядок и содержимое; старый regex-парсер мог
пропускать такие части. Передача готовых argv дополнительно проверена на путях
с пробелами, без shell-расширения и без потери повторяющихся параметров.

В VM обнаружилось, что nfqws при root dry-run проверяет доступность файлов с
пониженным UID, а приватный staging-каталог 0700 закономерно недоступен.
Минимальный эксперимент подтвердил: обычная проверка отказала с `Permission
denied`, проверка того же набора с `--uid=0:0` прошла. Приватные права не
ослаблялись. Добавлены два этапа: предварительная root-проверка внутри 0700 и
обязательная обычная проверка окончательного кандидата до остановки сервиса.
Проверочный UID не попадает в рабочие аргументы. Для обоих режимов есть тесты,
в том числе отказ публичной проверки без переключения версии.

Офлайн-тесты также проверяют: неизвестные глобальные/DPI-параметры, попытки
исполнения shell, выход из допустимых путей, symlink, подмену manifest/файлов,
неполный кэш, коллизии имён, отсутствие активного профиля и выбранную custom-
стратегию. Парсер и доверенный установщик не берутся из stage. Загрузчик
доверенного модуля не создаёт `__pycache__` в установленной версии.

## Ограничения

Сеть VM — QEMU slirp/user-mode NAT. HTTP 200 от YouTube/Discord не доказывает
обход DPI: соединение может реконструироваться NAT, сайты доступны без zapret.
Не проверены видео/CDN, QUIC и голосовой Discord, другие дистрибутивы, iptables,
другие версии движка или будущие форматы Flowseal. Неизвестные возможности
должны блокировать применение, а не пропускаться молча.

## Повторение и журналы

Сценарий `ci/vm_sync_smoke.py` запускается только в одноразовой VM с hostname
`zapret-integration`, маркером `/var/tmp/zapret-vm-provisioned` и явным
`--acknowledge-disposable-vm`. Он меняет гостевую систему и не является обычным
офлайн-тестом. Сначала обычный пользователь готовит source и cache, затем root:

```sh
sudo python3 ci/vm_sync_smoke.py install --source /home/vmtest/checkout \
  --cache /home/vmtest/sync-cache --acknowledge-disposable-vm
sudo systemctl reboot
# После повторного подключения к той же VM:
sudo python3 ci/vm_sync_smoke.py after-reboot --source /home/vmtest/checkout \
  --cache /home/vmtest/sync-cache --acknowledge-disposable-vm
```

Локальные исходные журналы сохранены в `/tmp/opencode/zapret-sync-vm/`:
`prepare.log`, `sync-install.log`, `user-timer.log`, `sync-after-reboot.log`,
`evidence.json`, `console.log`. Они не входят в репозиторий и могут исчезнуть при
очистке временных файлов. SSH-ключи VM в код и отчёт не включались.
